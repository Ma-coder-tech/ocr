## Architecture

The full-planner and issue-grounded builders now use one named, versioned provider schema. Reference fields contain fixed class-aware alias-token patterns rather than request-specific alias enums. `issueId`, provider input hash, issued-alias membership, permitted reference class, and the packet-specific allowed-evidence subset are enforced after structural parsing by the trusted Package B request map and existing planner validator.

The provider schema preserves fixed authority, admission, truth-effect, financial-mutation, customer-rendering, resolution-path, evidence-class, confidence, reconstruction, object-shape, and required-field constraints. It is not a free-form response contract.

The complete pre-change classification is in `dynamic-schema-inventory-2026-09-15.md`.
