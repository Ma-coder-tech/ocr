## Safe error diagnostics

Nested OpenRouter/provider metadata can now contribute an allowlisted code, parameter, normalized failure kind, diagnostic source, and fixed sanitized message. Arbitrary nested text is never retained. Tests cover credentials, authorization material, a business name, an account-like number, raw metadata, routing metadata, and private headers.

Recognized structured-output failures are represented as `JSON_SCHEMA_REJECTED` with the fixed message `Provider rejected the structured-output JSON schema.` Unknown messages are reduced to a fixed unclassified-provider-error message.

No prompt, packet, provider schema, privacy behavior, reference set, retry policy, fallback policy, production route, canonical/RD truth, research behavior, admission behavior, or customer output was changed.
