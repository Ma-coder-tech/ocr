# Package B — Outbound Source-Reference Privacy Containment v1

Accepted baseline: `e268d6e48823a15996c4c5c401459dab710f1a5a`.

Mode: offline-only engineering validation. Provider calls, network calls, research, evidence admission, customer output, production routing, and truth mutation were all zero.

## Implementation

Provider-bound fact, statement-evidence, governed-evidence, and economic-charge references are replaced with typed request-scoped opaque aliases. The internal-to-provider map stays in process on the request object and is never serialized. The provider packet hash is rebound over the aliased packet. Provider output is accepted only after request-map binding, typed alias validation, local reverse mapping, and the unchanged planner validator all succeed.

The boundary rejects malformed, unknown, cross-request, wrong-class, duplicated, raw internal, and source-like references. It also rejects missing/colliding/mismatched maps and unsuppressed possible natural-person business names.

## Engineering finding and next package

Package B closes the outbound internal-reference and source-identity disclosure boundary while retaining exact local grounding. It intentionally does not remove packet-specific enum expansion. Package A diagnostics therefore remain applicable, and Package C — stable provider-facing schema — remains the recommended next package, subject to separate Product authorization.
